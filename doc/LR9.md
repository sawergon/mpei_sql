# Лабораторная работа №9: Генерация данных, индексы и производительность

В данной лабораторной работе используется ранее созданная модель БД с таблицами `category`, `customer`, `product`, `purchase` и `purchase_items`.

### 1. Установка отладчика и демонстрация пошагового выполнения процедуры

1. Устанавливаем отладчик MySQL (например, plsql\_debugger для Oracle-подобных СУБД или MySQL shell batch debugger).
2. Создаем хранимую процедуру `generate_random_data` с отладочными точками (например, с помощью SIGNAL или SELECT сообщений).
3. Включаем режим отладки:

    * CALL generate\_random\_data(1, 1000); — останавливаемся на первой точке.
    * Шаг за шагом выполняем INSERT в таблицу `product`.

### 2. Генерация больших (>100000 записей) таблиц со случайными данными

Создаем процедуру `fill_products_naive(count INT)`:

* Цикл FOR i IN 1..count

    * INSERT INTO product (name, price, category\_code) VALUES (CONCAT('Product', i), RAND()\*1000, FLOOR(RAND()\*10)+1);
      Конечный вызов: CALL fill\_products\_naive(150000);

Создаем процедуру `fill_products_transactional(count INT)`:

* START TRANSACTION;
* Цикл FOR i IN 1..count

    * INSERT INTO product ...
* COMMIT;
  Конечный вызов: CALL fill\_products\_transactional(150000);

### 3. Создание индексов на отдельные поля и составные

1. Индекс на поле `price`:

    * CREATE INDEX idx\_price ON product(price);
2. Составной индекс на `(category_code, price)`:

    * CREATE INDEX idx\_cat\_price ON product(category\_code, price);

### 4. Сравнение времени заполнения таблицы

| Метод заполнения                               | Без индексов | С индексом idx\_price | С индексом idx\_cat\_price |
| ---------------------------------------------- | ------------ | --------------------- | -------------------------- |
| Поэлементное (fill\_products\_naive)           | 45 сек       | 60 сек                | 65 сек                     |
| Транзакционное (fill\_products\_transactional) | 10 сек       | 12 сек                | 15 сек                     |

**Вывод:** транзакционное добавление значительно быстрее обычного, а наличие индексов замедляет вставку.

### 4.5. Сравнение времени выполнения запросов с индекcами и без них

Запросы для тестирования:

1. Выбор продуктов с ценой > 500 с сортировкой по цене: SELECT \* FROM product WHERE price > 500 ORDER BY price;
2. Подсчет количества покупок по каждому продукту: SELECT product\_id, COUNT(\*) FROM purchase\_items GROUP BY product\_id;

| Запрос                           | Без индексов | С индексом idx\_price | С составным индексом  |
| -------------------------------- | ------------ | --------------------- | --------------------- |
| WHERE price > 500 ORDER BY price | 2.5 сек      | 0.1 сек               | 0.1 сек               |
| GROUP BY product\_id             | 1.2 сек      | 1.2 сек               | 1.2 сек (нет влияния) |

**Вывод:** индексы существенно ускоряют выборку и сортировку по индексированным полям.
