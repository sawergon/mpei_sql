# Лабораторная работа №10: Партицирование и производительность

## 1. Исходная модель базы данных

### 1.1. Структура исходной модели

```sql
CREATE TABLE category
(
    code INT NOT NULL PRIMARY KEY,
    name VARCHAR(255) NULL
);

CREATE TABLE customer
(
    id   INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL
);

CREATE TABLE product
(
    id            INT AUTO_INCREMENT PRIMARY KEY,
    name          VARCHAR(255) NULL,
    price DOUBLE DEFAULT 0.0,
    category_code INT NULL,
    FOREIGN KEY (category_code) REFERENCES category (code) ON DELETE CASCADE
);

CREATE TABLE purchase
(
    id          INT AUTO_INCREMENT PRIMARY KEY,
    date        DATETIME NULL,
    price DOUBLE DEFAULT 0.0,
    customer_id INT NULL,
    FOREIGN KEY (customer_id) REFERENCES customer (id) ON DELETE CASCADE
);

CREATE TABLE purchase_items
(
    amount      INT DEFAULT 0,
    product_id  INT NULL,
    purchase_id INT NULL,
    inorder_price DOUBLE DEFAULT 0.0,
    FOREIGN KEY (product_id) REFERENCES product (id) ON DELETE CASCADE,
    FOREIGN KEY (purchase_id) REFERENCES purchase (id) ON DELETE CASCADE
);
```

### 2.4. Представление

```sql
CREATE VIEW new_schema.recent_high_value_purchases AS
SELECT c.name  AS customer_name,
       p.date  AS purchase_date,
       p.price AS total_amount
FROM new_schema.purchase p
         JOIN new_schema.customer c ON p.customer_id = c.id
WHERE p.price > 1000
ORDER BY p.date DESC LIMIT 10;
```

## 4. Выводы

1. Партицирование значительно улучшает производительность запросов за счет сокращения объема сканируемых данных
2. Оптимальный выбор типа партицирования зависит от характера запросов:
    - LIST для категорий (дискретные значения)
    - RANGE для дат (временные данные)
    - RANGE для purchase_id (последовательные идентификаторы)
3. Необходимо учитывать ограничения MySQL при работе с партицированными таблицами:
    - Нельзя использовать внешние ключи в партицированных таблицах
    - Первичный ключ должен включать колонки партицирования
    - Нельзя использовать функции в выражениях партицирования
4. Использование триггеров позволяет автоматизировать поддержку числовых значений для партицирования по дате
