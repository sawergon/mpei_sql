# Отчет по SQL-запросам

## 1. Список клиентов и товаров
```sql
SELECT name AS entity_name, 'customer' AS entity_type
FROM customer
UNION
SELECT name AS entity_name, 'product' AS entity_type
FROM product;
```

### Описание
Этот запрос объединяет данные из двух таблиц: `customer` и `product`, создавая единый список всех сущностей (клиентов и товаров). Используется оператор `UNION`, который объединяет результаты двух SELECT-запросов, удаляя дубликаты.

### Структура результата
- `entity_name`: имя сущности (как клиента, так и товара)
- `entity_type`: тип сущности ('customer' или 'product')

### Применение
Полезен для получения общего списка всех сущностей системы в едином формате, что может быть полезно для админ-панели или поисковых систем.

## 2. Иерархия категорий
```sql
ALTER TABLE category ADD parent_code INT;

INSERT INTO category (code, name, parent_code) VALUES
    (11, 'Бытовая электроника', 1),
    (12, 'Компьютерная периферия', 1);

WITH RECURSIVE category_tree AS (
    SELECT code, name, parent_code, 0 AS level
    FROM category
    WHERE code = 1  -- Корневая категория

    UNION ALL

    SELECT c.code, c.name, c.parent_code, ct.level + 1
    FROM category c
             JOIN category_tree ct ON c.parent_code = ct.code
)
SELECT * FROM category_tree;
```

### Описание
Этот набор запросов реализует иерархическую структуру категорий:
1. Добавляется поле `parent_code` для хранения связи с родительской категорией
2. Добавляются две подкатегории к корневой категории (код 1)
3. Используется рекурсивный CTE (Common Table Expression) для построения дерева категорий

### Структура результата
- `code`: код категории
- `name`: название категории
- `parent_code`: код родительской категории
- `level`: уровень вложенности (глубина)

### Применение
Позволяет эффективно работать с иерархическими данными, такими как категории товаров, где одна категория может иметь подкатегории.

## 3. Ранжирование покупок
```sql
SELECT
    c.name AS customer_name,
    p.date AS purchase_date,
    p.price AS purchase_total,
    RANK() OVER (PARTITION BY c.id ORDER BY p.price DESC) AS price_rank,
    SUM(p.price) OVER (PARTITION BY c.id ORDER BY p.date) AS running_total
FROM purchase p
         JOIN customer c ON p.customer_id = c.id;
```

### Описание
Этот запрос выполняет сложный анализ данных о покупках:
1. Объединяет данные о покупках с данными о клиентах
2. Использует оконные функции для:
   - Ранжирования покупок по стоимости для каждого клиента (`RANK()`)
   - Вычисления накопительной суммы покупок для каждого клиента (`SUM()`)

### Структура результата
- `customer_name`: имя клиента
- `purchase_date`: дата покупки
- `purchase_total`: сумма покупки
- `price_rank`: ранг покупки по стоимости (1 - самая дорогая)
- `running_total`: накопительная сумма покупок клиента

### Применение
Полезен для маркетингового анализа, позволяет:
- Определить крупнейшие покупки каждого клиента
- Отслеживать накопительную стоимость покупок
- Выявлять наиболее ценных клиентов
- Проводить сегментацию клиентов по стоимости покупок
